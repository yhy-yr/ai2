# 医生工作区侧栏审查

日期：2026-06-19

## 审查范围

- 医生工作区左侧“今日接诊”面板
- 删除“已完成 / 已撤回”后的状态筛选、数量、空状态和响应式布局
- 依据：当前源码与生产构建结果

## 验证结果

1. **生产构建：正常**
   - `npm run build` 通过。
   - 状态筛选已只保留“待接诊 / 接诊中”，布局已调整为两列。
   - 默认状态回退逻辑也只会选择这两个仍然可见的状态。

2. **数量语义：存在问题（中优先级）**
   - 面板标题下的“X 人”仍按全部预约计算，包含已完成和已撤回记录。
   - 删除两个历史状态入口后，这个数字可能大于两个可见筛选数量之和，容易让医生误以为有患者记录丢失。
   - 建议只统计 `waiting + active`，或把文案改成“全部预约 X 人”。

3. **空状态文案：不够准确（低优先级）**
   - “待接诊”和“接诊中”无数据时都显示“当前暂无接诊患者”。
   - 建议按当前筛选显示“暂无待接诊患者”或“暂无接诊中患者”。

4. **筛选状态的无障碍表达：存在风险（低优先级）**
   - 当前选中状态只通过 `.active` 的视觉样式表达。
   - 建议为按钮增加 `aria-pressed`，或采用 `tablist / tab / aria-selected` 语义。

5. **窄屏布局：存在结构风险（中优先级）**
   - 页面宽度小于 1120px 时，左侧患者面板、主内容和右侧 AI 面板整体纵向堆叠。
   - 医生需要先滚过功能区和患者队列才能看到主工作区，移动端任务优先级不合理。
   - 建议窄屏下把两个侧栏改为可展开抽屉，主工作区保持第一屏可见。
